※ この記事は、[SPFx Dev Skills for SPFx 1.24.1: tested across agents and models](https://devblogs.microsoft.com/microsoft365dev/spfx-dev-skills-for-spfx-1-24-1-tested-across-agents-and-models/) の抄訳です。最新の情報はリンク先をご確認ください。この記事は Microsoft 365 Copilot および GitHub Copilot を使用して抄訳版の作成が行われています。

スキルの指示を書き換えることは簡単です。AI コーディング エージェントがその指示に従うか、またエージェントが独力で行う場合より良い結果を出すかを確かめるには、さらに検証が必要です。

本日、SharePoint Framework (SPFx) v1.24.1 をサポートし、既存のプロジェクトを React 18 に移行する手順を含む [SPFx Dev Skills](https://github.com/SharePoint/spfx-dev-skills) v1.1.2 をリリースしました。このスキルの効果を確かめるため、エージェントとモデルの 7 通りの組み合わせで 105 回の評価を行いました。更新したスキルにより、すべての組み合わせでアップグレードの品質が向上しました。また、予想していなかったこともわかりました。タスクに特化したガイダンスがあれば、この評価では、低コストのモデルやモデル ルーターでも、高価なモデルと同じ平均アップグレード スコアを達成できました。

SPFx Dev Skills は、AI コーディング エージェントが現在のツールや推奨プラクティスを使って SPFx プロジェクトを作成・アップグレードできるよう、バージョンに応じた指示を提供します。

## v1.1.2 の変更点

今回の更新では、スキルを SPFx v1.24.1 に対応させました。次の内容を扱います。

- SPFx v1.24.1 のプロジェクトの作成と**アップグレード**
- 既存の React コードを React 18 の API に**移行**
- Heft、依存関係のバージョン、対象となる SPFx リリースでサポートされる Node.js のバージョンなど、最新の**ツール要件**
- [CLI for Microsoft 365](https://aka.ms/cli-m365) の**アップグレード レポート**を最後まで読み、内容を適用する方法
- Fluent UI v9 と PnPjs に関する更新された**推奨事項**

エージェントが元から持つ知識は、最新の SPFx リリースに対応していない場合があります。最初のリリースと同様に、このスキルは、開発者が実際に使用しているバージョンに合わせた判断ルールを提供し、その差を補います。

SPFx Dev Skills をすでに使っている場合は、最新バージョンに更新してください。初めて使う場合は、[GitHub リポジトリ](https://github.com/SharePoint/spfx-dev-skills)でインストール手順を確認できます。

## 新規プロジェクトと比較してアップグレードを評価

[SPFx Dev Skills の背景](https://devblogs.microsoft.com/microsoft365dev/behind-spfx-dev-skills-testing-what-agents-know-and-fixing-what-they-miss/)では、評価を通じて、エージェントが SPFx についてすでに把握していることと、追加の支援が必要な点を示しました。今回のリリースでは、まず 1 つのシナリオ、既存の SPFx プロジェクトを v1.24.1 にアップグレードする作業を、同じ方法で評価しました。新しく作成した SPFx v1.24.1 プロジェクトで想定される依存関係、構成、React 18 API の変更と比較しました。スコアが 100% であれば、アップグレードが評価基準のすべての項目を満たしたことを意味します。

各エージェントとモデルで、スキルなし、v1.0、v1.1.2 の 3 通りの条件でアップグレードを実行しました。ベースラインはエージェントが既存の知識で行うことを示し、v1.0 は前のリリースですでに得られていた改善の程度を示します。

エージェントとモデルの選定では、SPFx コミュニティについて把握していることと、[SPFx 開発者アンケート](https://devblogs.microsoft.com/microsoft365dev/your-voice-shapes-spfx-take-our-developer-survey/)から得た初期の情報を組み合わせました。Visual Studio Code の GitHub Copilot Chat では、Claude Sonnet 5.5、Claude Opus 5.5、GPT-6 Luna、GPT-6.1 Terra をテストしました。Copilot Chat では、単一のモデルではなく、リクエストごとにモデルを選択するルーターである Copilot Fusion もテストしました。Claude Code CLI では、Claude Sonnet 5.5 と Claude Opus 5.5 をテストしました。すべての評価は Windows で実行しました。エージェントの実行結果には非決定性があるため、各構成を 5 回ずつ実行しました。エージェントとモデルの 7 通りの組み合わせで、合計 105 回の実行となります。

## 更新したスキルがすべての組み合わせで差を縮める

## 結果が向上しても、コストが下がるとは限らない

GitHub Copilot Chat の Claude Sonnet 5.5 では、スキルなしの 47% から v1.1.2 の 100% にスコアが上がり、1 回あたりのコストは $0.49 から $0.40 に下がりました。GPT-6.1 Terra も同様に、コストが $0.33 から $0.23 に下がる一方で、スコアは 59% から 98% に上がりました。GitHub Copilot Chat の Opus 5.5 は、スキル単独でも高いスコアでしたが、スキルなしの $1.24 から v1.1.2 の $0.82 へとコストが下がりました。

一方、コストが上がった組み合わせもあります。Claude Code の Opus 5.5 は 94% から 100% に向上しましたが、コストは 1 回あたり $0.25 から $0.32 に増えました。GitHub Copilot Chat の Copilot Fusion も $0.01 から $0.02 になりました。v1.0 と比較すると、v1.1.2 では 7 通りのうち 6 通りで推定推論コストが高くなりました。アップグレード レポートを最後まで読んで適用することで、追加のトークンが必要になる可能性があります。すべての構成について、品質とコストを並べて示しています。

## 推定推論コストのわずかな割合で同じアップグレード スコアを達成

スキルなしの GPT-6 Luna は、すべての組み合わせの中で最も低い 27% でした。v1.1.2 を使うと、Claude Code の Opus 5.5 と同じ 100% になりました。GitHub Copilot Chat では、更新したスキルを使った Luna の平均コストは 1 回あたり $0.03 でした。同じスキルを使った Opus 5.5 は $0.82 で、同じ平均スコアを達成するためのコストは約 27 倍でした。

Copilot Fusion はさらに低コストでした。スキルなしでは 32% でしたが、v1.1.2 を使うと、1 回あたり $0.02 のコストで 100% に達しました。これは Opus 5.5 の約 41 分の 1 のコストです。Fusion はリクエストごとにモデルを選ぶため、この結果を特定の単一モデルに帰属させることはできません。評価の実行時に Fusion が行ったルーティングの判断が反映されています。

今回は 1 つのアップグレード シナリオを評価しました。ほかの SPFx タスクでは、小規模なモデルにはない機能が必要になるかもしれません。それでも、大規模なモデルを既定で選ぶのをやめるべき理由となる結果です。タスクに特化したガイダンスがあれば、小規模なモデルやルーターで十分な場合があります。

## 評価結果を受けてリリース内容を変更

v1.0 から v1.1.2 に進んだことに気付いたかもしれません。最初の v1.1 を評価したところ問題が見つかったため、リリース前に修正しました。

特に興味深かったのは、エージェントの軌跡、つまりプロジェクトのアップグレード中にエージェントが行う操作の完全な流れからわかったことです。エージェントは CLI for Microsoft 365 を使って SPFx のアップグレード レポートを生成することを把握していました。しかし、一部の実行では、レポートを生成しても一部分しか読んでいませんでした。レポートにはアップグレードに必要な手順がすべて記載されています。そのため、途中で読むのをやめると、プロジェクトのアップグレードが不完全になります。

そこで、複数回に分けて読む必要があっても、最後の `## Summary` セクションまでアップグレード レポート全体を読むよう、スキルの指示に明記しました。また、結果を左右する手順に集中できるよう、セットアップとアップグレードのガイダンスの一部を簡潔にしました。

操作履歴を確認したことで、こうした的を絞った変更を特定できました。スコアからはエージェントの実行品質がわかり、軌跡からは成功・失敗の理由と次の実行で変更すべき点がわかります。v1.1.2 は、リリース前にこのサイクルを何度か繰り返しました。

## 今後の予定

最初にアップグレードを選んだのは、依存関係、構成、ツール、アプリケーション コードにまたがる変更をエージェントが調整する必要があるためです。今後は、評価する SPFx 開発シナリオを増やし、エージェントやモデルの変化に合わせて評価を再実行します。モデルの性能が上がれば、現在役立っているガイダンスが不要になる場合もあります。同じ評価を再実行することで、どのガイダンスを維持し、どれを削除するかを根拠に基づいて判断できます。

評価をコミュニティで利用できるようにする取り組みも進めています。貢献者がスキルの変更案をプル リクエストとして送る前にテストし、その変更がアップグレードの品質を高めるか、またどのくらいのコストがかかるかを確認できるようになります。

## 最新の SPFx Dev Skills を入手

AI コーディング エージェントを使って SPFx ソリューションを作成・アップグレードする場合は、[GitHub の SPFx Dev Skills v1.1.2](https://github.com/SharePoint/spfx-dev-skills)をお試しください。SPFx v1.24.1 と React 18 への移行をサポートし、SPFx コミュニティで使われているエージェントとモデルを対象に、その効果を測定しています。

プロジェクトで試し、エージェントが作成した内容を確認してください。結果に誤りや意外な点があれば、[Issue を作成](https://github.com/SharePoint/spfx-dev-skills/issues)し、次に評価してほしい SPFx のシナリオをお知らせください。その情報を基に、スキルで教えるべき内容と、問題がスキル、ツール、ドキュメントのどこにあるかを判断できます。
