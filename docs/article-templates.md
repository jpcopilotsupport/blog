# 記事のひな形とメタデータ

以下の例をコピーし、`source/_posts/<記事スラッグ>.md` として保存します。
この文書は参照用で、ブログの公開用ディレクトリには出力しません。
`scaffolds/post.md` と `scaffolds/draft.md` にも管理項目を設定しています。

## 自作記事

```markdown
---
title: "記事タイトル"
date: 2026-10-23 13:00
tags:
  - Microsoft 365 Copilot
editorial:
  authors:
    - your-github-handle
  type: original
  version: "1.0.0"
---
記事の本文を記載します。
```

## 抄訳記事

```markdown
---
title: "日本語の記事タイトル"
date: 2026-10-23 13:00
tags:
  - Microsoft 365 Copilot
editorial:
  authors:
    - your-github-handle
  type: translation
  version: "1.0.0"
  source_url: https://example.com/original-article/
---
※ この記事は、[Original article title](https://example.com/original-article/) の抄訳です。最新の情報はリンク先をご確認ください。この記事は Microsoft 365 Copilot および GitHub Copilot を使用して抄訳版の作成が行われています。

原文の意味と構造を維持した日本語本文を記載します。
```

## 各項目のルール

| 項目 | ルール |
|---|---|
| `title` | 空でない日本語タイトル。コロンを含む場合は引用符で囲む |
| `date` | 日本語記事の初回公開日時。新規記事は日本時間の `YYYY-MM-DD HH:mm`。原文の日付をコピーしない |
| `tags` | 単一タグは文字列、複数タグは配列。抄訳記事は必須。自作記事では省略・空欄も許容 |
| `lastupdate` | 更新時だけ追加する日本時間の `YYYY-MM-DD`。新規記事には設定しない |
| `editorial.authors` | 必須。実際の執筆・翻訳担当者の GitHub ハンドル。`@` なし、1 人でも配列、重複不可。チーム共通の識別子も使用可能 |
| `editorial.type` | 必須。自作記事は `original`、抄訳記事は `translation` |
| `editorial.version` | 必須。記事のバージョンを引用符付きの `"MAJOR.MINOR.PATCH"` で記録。先頭ゼロ・接尾辞は使わない。抄訳記事の初版は原文の版番号に従う。詳細は [バージョンの管理](#バージョンの管理) を参照 |
| `editorial.source_url` | 抄訳記事のみ必須。確認した正規の HTTP(S) URL。本文冒頭の出典リンクと一致させる。自作記事では項目自体を省略 |

`your-github-handle`、タイトル、日時、タグ、出典の例は実際の値に置き換えてください。
複数人で執筆した場合は `authors` の配列に追加します。
担当者が不明な場合は推測せず確認し、Bot や原文の著者を自動的に日本語記事の著者にしません。
既存記事の更新では既存の著者情報を保持し、担当者が明示された場合のみ追加・変更します。

レビュー担当者・承認状態はフロントマターに追加せず、PR の履歴で管理します。

## バージョンの管理

`editorial.version` は記事の版番号であり、フロントマター形式や製品、API のバージョンではありません。
抄訳記事では原文に記事バージョンがあるかを確認し、次のルールで設定します。

### 原文に `A.B` 形式の記事バージョンがある場合

先頭 2 段を翻訳に使用した原文の版番号に合わせ、3 段目を日本語側の修正番号として使います。
新規記事でも、原文が `2.3` なら `"1.0.0"` ではなく `"2.3.0"` で開始します。
原文の新版を翻訳へ反映したら、先頭 2 段をその版番号に合わせ、3 段目を `0` に戻します。

| 操作 | `editorial.version` |
|---|---|
| 原文 `1.0` の初回翻訳 | `"1.0.0"` |
| 原文 `1.0` のまま日本語の誤字などを修正 | `"1.0.1"` |
| さらに日本語だけを修正 | `"1.0.2"` |
| 原文 `1.1` の変更を反映 | `"1.1.0"` |
| 原文 `2.0` の変更を反映 | `"2.0.0"` |

### 原文に記事バージョンがない場合

Developer 系ブログなど、原文に記事バージョンがない場合は `"1.0.0"` から開始します。
原文の変更を反映する更新では 1 段目を加算し、2 段目と 3 段目を `0` に戻します。
原文が変わっていない場合の日本語修正では 3 段目だけを加算し、2 段目は `0` のままにします。

| 操作 | `editorial.version` |
|---|---|
| 初回翻訳 | `"1.0.0"` |
| 原文が変わっていない状態で日本語だけを修正 | `"1.0.1"` |
| 原文の変更を反映 | `"2.0.0"` |
| 同じ原文のまま日本語だけを修正 | `"2.0.1"` |
| 次の原文の変更を反映 | `"3.0.0"` |

原文を取得できていないなど、版番号がないと確認できない場合は、このルールへ自動的に
切り替えず、推測せずに確認します。非対話の作業では理由を報告して終了します。
既存記事や未移行記事も、対応する原文の版を確認して同じルールを適用します。
既存の `"1.0.0"` が原文 `1.0` との対応を確認済みであるとは限りません。

### 自作記事・共通の運用

自作記事は `"1.0.0"` から開始し、誤字・リンク修正は PATCH、説明追加は MINOR、
大幅な内容刷新は MAJOR を上げる目安とします。
いずれの記事も公開する改訂単位で更新し、レビューのたびに機械的に加算しません。
原文に変更があっても日本語記事に反映する変更がなく、改訂を公開しない場合は、
バージョンだけを更新しません。記事更新時は `lastupdate` も更新します。
検証スクリプトは 3 段の形式を検証しますが、原文の版番号や変更内容との対応は PR で確認します。

## 原文との逐文レビュー

対話型の `/translate` と `/update` では、翻訳・更新案の作成、検証、サイト生成を行い、
プレビューをブラウザーで開いてから、次の照合結果を表示して実行者に表現を選んでもらいます。
プレビューを見ながら判断できるよう、選択中もサーバーを維持します。
更新では変更箇所だけでなく記事全体が対象です。初期の更新案に変更がない場合も既存記事を
プレビューし、このレビューを行います。

### 照合範囲と観点

- 取得した原文の各文に見出しと連番 (例: `S001`) を対応付け、訳文と 1 文ずつ照合します。
  1 文を複数の日本語文に分けた場合や、複数文をまとめた場合も対応を追跡します。
- 原文から訳文への確認だけでなく、訳文から原文へも確認し、訳抜け・重複・根拠のない加筆を探します。
  タイトル、見出し、箇条書き、表、注意書き、画像キャプション、リンク、強調も対象です。
  文ではない要素にも識別子を付けます。コードや URL は内容の一致を確認します。
- 否定、条件、例外、対象範囲、主語、数値、日時、提供状況、製品名が保持されているか確認します。
- `must` / `should` / `may` / `can`、推奨・必須、可能性・断定、予定・提供済みなどの
  表現の強弱が一致しているか確認します。日本語の自然さだけを理由に原文の確度を変えません。
- 原文の取得不足や対応関係の不明点は「未確認」として明示し、推測で「問題なし」にしません。

### 確認結果の表示

プレビューを開いた後、チャットにプレビュー URL と見出し別の照合範囲・確認件数・未確認件数を表示し、
全体を確認したことが追跡できるようにします。
そのうえで、問題や選択の余地がある箇所を次の一覧にします。原文は要旨または判断に必要な最小限の
短い引用と出典内の位置を示し、記事全文を転載しません。訳抜けは現行訳を「なし」とします。

| ID / 位置 | 原文の要旨・根拠 | 現行訳 (A) | 修正候補 (B) | 分類・意味や強弱の違い | 推奨と理由 | 実行者の選択 |
|---|---|---|---|---|---|---|
| S012 / 見出し名 | 利用できる可能性を示す | 必ず利用できます | 利用できる場合があります | 断定が強い | B: 原文の可能性を維持 | 未選択 |

意味の不一致・訳抜けなどの修正推奨と、意味は同じで自然さの好みによる任意の提案を区別します。
問題のない箇所は見出し別の件数に含め、候補を無理に作りません。候補がない場合も照合結果を表示します。
件数や表は実際に確認した内容だけを記録し、未確認があればその位置と理由を示します。

### 実行者の選択と反映

- 一覧を表示した時点で止まり、利用可能なユーザー確認ツールで各 ID の「A を維持」
  「B を採用」「別案を指定」「保留」を確認します。明示的に選べる一括採用・一括維持も可とします。
  確認ツールがない場合は判断待ちとし、選択を推測して後続処理へ進みません。
- 修正候補は選択前に自動適用しません。既定選択、未回答、確認の辞退を承認とみなさず、
  未選択・保留が残る場合はレビューを完了扱いにしません。表示中のプレビューは維持します。
- 実行者が選んだ表現だけを反映し、変更箇所を原文と再照合します。別案で新たな意味の差が生じた場合は
  再提示します。意味の不一致が残る現行訳を選んだ場合も、その事実と選択理由を結果に残します。
- 選択した表現の反映後は検証とサイト生成を再実行し、プレビューを再読み込みして、
  実行者に採用した表現を表示上でも確認してもらいます。検証に失敗した場合は完了扱いにしません。
- 候補がない場合は、その結果を実行者に提示して先へ進んでよいか確認します。
  原文の取得不足による未確認は表現の選択で解消したことにせず、追加取得や確認で解決するまで中断します。
- プレビュー後に訳文を変更した場合も、変更箇所と前後の文脈を再照合し、新たな候補は同じ手順で選択します。
  同じ公開改訂内のレビュー対応だけを理由に、記事バージョンを重ねて加算しません。
- 最終報告に確認範囲、件数、採用・維持した ID と選択内容、残る注意点を含めます。
  照合一覧は記事本文やフロントマターに追加しません。

## 公開範囲

`editorial` はページ本文、HTML メタ情報、Atom フィード、サイトマップには出力しません。
ただし公開リポジトリの Markdown からは誰でも読めます。
メールアドレス、社内限定情報、秘密情報は記載しないでください。
抄訳記事の本文冒頭の出典リンクは従来どおり読者に公開します。

## 検証

```powershell
npm.cmd run validate:translations -- --all
npm run test:translation-validation
npm run build
```

Windows PowerShell では引数を確実に渡すため `npm.cmd` を使用しています。
他のシェルでは `npm run validate:translations -- --all` を使用できます。

互換性のためコマンド名は従来のままですが、自作記事もメタデータの検証対象です。
PR では変更された記事について検証します。公開終了案内など `source/_posts` 外の
固定ページは記事用メタデータの必須チェック対象外です。
テストでは独立した一時ディレクトリにサイトを生成し、管理情報が公開出力に含まれないことも確認します。
